# L4 通信加密应用手册

本文面向部署和联调人员，说明如何为 AP/DEV 之间的 SBUS、MAVLink 和 TAP 透传链路配置加密。

开始操作前只需记住一条原则：**同一条链路的 AP 和 DEV 两端必须使用相同的 port、加密模式和密钥。** 只配置一端时，业务会因两端参数不一致而中断。

## 1. 先选择配置方式

| 需求 | 使用方式 | 立即生效 | 重启或 socket 重建后保留 |
| --- | --- | :---: | :---: |
| 修改已经运行的 SBUS/MAVLink socket | `l4_socket_encrypt` | 是 | 否 |
| 保存 SBUS/MAVLink 的持久配置 | `l4_socket_encrypt --minidb` | 否 | 是 |
| 立即生效并持久保存 | 先执行运行态命令，再执行同参数的 `--minidb` 命令 | 是 | 是 |
| 创建加密的 TAP 透传 socket | 启动 `l4_tuntap -e ...` | 创建时生效 | 进程重连时沿用启动参数 |

> `l4_socket_encrypt` 的运行态配置和 MiniDB 持久配置是两套独立配置。写入 MiniDB 不会修改当前 socket；只执行运行态命令也不会自动写入 MiniDB。

常用业务端口：

| 业务 | Socket port | 建议工具 |
| --- | ---: | --- |
| SBUS | `0` | `l4_socket_encrypt` |
| MAVLink | `1` | `l4_socket_encrypt` |
| TAP 网络透传 | 默认 `3` | `l4_tuntap` |

`l4_tuntap` 可通过 `-P` 修改端口。修改后两端必须使用相同端口，并确认没有与固件已有业务端口冲突。

## 2. 五分钟完成 SBUS 加密

下面以最常见的单 DEV 场景为例：从 AP 所在主机执行全部命令，DEV 位于 AP slot 0，为 SBUS port 0 配置 AES128，并同时更新当前 socket 和 MiniDB。

示例密钥仅用于演示，生产环境必须替换：

```text
00112233445566778899aabbccddeeff
```

### 2.1 检查环境

1. 确认 AP 和 DEV 两端的 `l4_daemon` 已启动。
2. 确认 AP/DEV 已配对，无线链路正常。
3. 确认 SBUS 在未加密状态下能够通信，目标 socket 已由固件创建。
4. 暂停 SBUS 业务流量，避免两端切换期间产生无效数据。

只有一台设备时，daemon 设备序号通常为 `-i 0`。

### 2.2 更新 AP 侧

先立即更新 AP 当前运行的 socket，再将相同配置写入 MiniDB：

```sh
./l4_socket_encrypt -i 0 -s 0 -P 0 -e aes128 \
  -k 00112233445566778899aabbccddeeff
./l4_socket_encrypt -i 0 --minidb -s 0 -P 0 -e aes128 \
  -k 00112233445566778899aabbccddeeff
```

### 2.3 从 AP 更新 DEV 侧

`-R` 表示让命令在无线对端执行。同样先更新 DEV 当前运行的 socket，再写入 MiniDB：

```sh
./l4_socket_encrypt -i 0 -R 0 -s 0 -P 0 -e aes128 \
  -k 00112233445566778899aabbccddeeff
./l4_socket_encrypt -i 0 -R 0 --minidb -s 0 -P 0 -e aes128 \
  -k 00112233445566778899aabbccddeeff
```

如果已经登录 DEV 所在主机，也可以不使用 `-R`，直接在 DEV 侧执行与 2.2 相同的两条命令。

### 2.4 查询并验收

查询 AP 和 DEV 的当前运行状态：

```sh
./l4_socket_encrypt -i 0 -s 0 -P 0 -g
./l4_socket_encrypt -i 0 -R 0 -s 0 -P 0 -g
```

确认两端均启用 AES128 后，恢复 SBUS 流量并验证控制数据。命令返回成功只表示设备接受了配置，**实际 SBUS 数据正常才代表端到端配置正确**。

如需验证持久配置，可以继续查询两端 MiniDB：

```sh
./l4_socket_encrypt -i 0 --minidb -s 0 -P 0 -g
./l4_socket_encrypt -i 0 -R 0 --minidb -s 0 -P 0 -g
```

> **密钥安全：** MiniDB 查询会输出完整 AES 密钥。不要在共享终端、录屏、流水线日志或无人值守日志中执行上述查询。

最后重启设备或触发相关 socket 重建，再次查询运行状态并验证 SBUS 数据，以确认固件已恢复持久配置。

## 3. 理解 AP、DEV、`-R` 和 `-s`

### 3.1 两端如何对齐

通信能够正常解密，需要同时满足：

1. AP 和 DEV 配置的是同一条对端链路。
2. 两端配置的是同一个 socket port。
3. 两端使用相同的加密模式。
4. AES128/AES256 模式下，两端使用完全相同的密钥。

slot 表示“命令执行设备看到的对端链路”。当前例程按 1v1 场景说明：AP 与 DEV 的 remote slot 和命令目标 slot 均使用 0。

### 3.2 `-R` 和 `-s` 分别选择什么

- `-R [slot]`：选择命令在哪台无线对端设备上执行；不使用 `-R` 时在本端执行。
- `-s <slot>`：选择执行设备内部要配置的对端链路。

| 操作场景 | 参数写法 | 含义 |
| --- | --- | --- |
| 在 AP 本端配置 slot 0 的 DEV 链路 | `-s 0` | 命令在 AP 执行，目标链路是 DEV |
| 从 AP 进入 slot 0 的 DEV，再配置该 DEV 到 AP 的链路 | `-R 0 -s 0` | 命令在 DEV 执行，DEV 内的 AP 链路为 slot 0 |
| 登录 DEV 主机后直接配置到 AP 的链路 | `-s 0` | 命令在 DEV 本端执行，目标链路是 AP |

`-R` 默认使用 remote slot 0，`-R`、`-R 0`、`-R0` 和 `--remote=0` 表示相同目标。`-R` 只修改对端，不会同时修改本端。

## 4. 加密模式和密钥

| 模式 | 密钥要求 |
| --- | --- |
| `default` | 选择固件内置的默认加密方案和密钥，不传 `-k` |
| `aes128` | `-k` 必须提供 16 字节，即 32 个十六进制字符 |
| `aes256` | `-k` 必须提供 32 字节，即 64 个十六进制字符 |

密钥可以连续书写，也可以使用空格、冒号或逗号分隔。无论使用哪种格式，AP 和 DEV 两端的有效密钥字节必须完全一致。

启用默认加密：

```sh
./l4_socket_encrypt -i 0 -s 0 -P 0 -e default
```

启用 AES256：

```sh
./l4_socket_encrypt -i 0 -s 0 -P 1 -e aes256 \
  -k 000102030405060708090a0b0c0d0e0f101112131415161718191a1b1c1d1e1f
```

上述命令均需在对应 AP/DEV 两端执行；如需持久化，再使用相同参数分别执行 `--minidb` 命令。

## 5. 配置 SBUS 或 MAVLink

SBUS 和 MAVLink 的操作流程相同，主要区别是 port。建议不同业务使用不同密钥。

| 业务 | `-P` | 验收数据 |
| --- | ---: | --- |
| SBUS | `0` | 遥控或控制数据 |
| MAVLink | `1` | 遥测和命令数据 |

将下列模板中的 `<port>`、`<mode>` 和 `<key>` 替换成实际值。

```sh
# 在 AP 更新当前 socket
./l4_socket_encrypt -i 0 -s 0 -P <port> -e <mode> -k <key>

# 从 AP 远程更新 DEV 当前 socket
./l4_socket_encrypt -i 0 -R 0 -s 0 -P <port> -e <mode> -k <key>
```

需要重启后恢复时，分别在上述两条命令中增加 `--minidb` 并再次执行。使用 `default` 模式时删除 `-k <key>`。完成后应分别查询两端运行状态，并通过对应业务数据进行端到端验收。

## 6. 配置 TAP 透传加密

`l4_tuntap` 在创建 TAP socket 时通过 `-e` 指定模式，通过 `-k` 指定 AES 密钥。不指定 `-e` 时创建普通、未加密 socket。

以下示例在 AP 和 DEV 上使用 TAP 默认 port 3，并使用相同的 AES128 密钥。

AP 侧：

```sh
sudo ./l4_tuntap -I 192.168.144.55 -P 3 -e aes128 \
  -k 2031425364758697a8b9cadbecfd0e1f
```

DEV 侧：

```sh
sudo ./l4_tuntap -I 192.168.144.66 -P 3 -e aes128 \
  -k 2031425364758697a8b9cadbecfd0e1f
```

启动日志应分别显示 `encryption=aes128`，程序不会打印密钥。两端 TAP IP 应位于同一网段且不能冲突，可使用 `ping` 或 `iperf` 验证网络透传。

`l4_tuntap` 会保存本次启动使用的加密参数，断线重连并重新创建 socket 时继续使用这些参数。需要切换配置时，应使用一致的新参数重启两端 `l4_tuntap`，不要依赖 `l4_socket_encrypt` 临时修改正在运行的 TAP port。

## 7. 查询、关闭和持久化

### 7.1 查询运行状态

```sh
# 查询本端 slot 0、port 0
./l4_socket_encrypt -i 0 -s 0 -P 0 -g

# 通过 remote slot 0 查询 DEV 内部 slot 0、port 1
./l4_socket_encrypt -i 0 -R 0 -s 0 -P 1 -g
```

运行态查询显示是否启用以及加密模式，但不返回密钥。

### 7.2 查询 MiniDB

```sh
./l4_socket_encrypt -i 0 --minidb -s 0 -P 1 -g
```

MiniDB 查询结果说明：

- `state=unset`：该 slot/port 没有持久化记录，不等于已经显式关闭加密。
- AES128 返回完整的 16 字节密钥。
- AES256 返回完整的 32 字节密钥。
- `default` 或已关闭状态显示 `key=none`。

MiniDB 模式仅接受 port `0-3`。持久配置由支持该功能的固件在相关 UART、Ethernet 或 XDS socket 创建时恢复；它不保证应用自行创建的任意 socket 都会自动应用该配置。

### 7.3 关闭加密

关闭当前 SBUS 加密时，在 AP 和 DEV 两端分别执行：

```sh
./l4_socket_encrypt -i 0 -s 0 -P 0 -d
```

也可以从 AP 远程关闭 DEV：

```sh
./l4_socket_encrypt -i 0 -R 0 -s 0 -P 0 -d
```

如果还要清除重启后的加密状态，应在两端分别写入 MiniDB 关闭配置：

```sh
./l4_socket_encrypt -i 0 --minidb -s 0 -P 0 -d
./l4_socket_encrypt -i 0 -R 0 --minidb -s 0 -P 0 -d
```

只有两端均完成关闭后，未加密数据才能正常互通。

## 8. 参数速查

| 参数 | 说明 |
| --- | --- |
| `-h` | 显示帮助信息 |
| `-a <addr>` | daemon 地址，默认 `127.0.0.1` |
| `-p <port>` | daemon 端口，默认 `50000` |
| `-i <index>` | daemon 枚举的目标设备序号，默认 `0` |
| `-R [slot]` | 通过 remote ioctl 在无线对端执行，remote slot 默认 `0` |
| `-s <slot>` | 命令执行设备内部的目标链路 slot，默认 `0` |
| `-P <port>` | 目标 socket port，必须指定 |
| `-g` | 查询目标 port 的加密配置 |
| `--minidb` | 改为读写 MiniDB，不更新当前 socket |
| `-e <mode>` | 启用或切换为 `default`、`aes128`、`aes256` |
| `-k <hex>` | AES128/AES256 密钥 |
| `-d` | 关闭目标 port 加密 |

参数组合规则：

- 查询时单独使用 `-g`。
- 设置时，`-e` 和 `-d` 必须且只能指定一个。
- `-g` 不能与 `-e`、`-d` 或 `-k` 同时使用。
- `default` 和 `-d` 不允许携带 `-k`。
- AES128/AES256 必须提供长度正确的 `-k`。

## 9. 故障排查

| 现象 | 原因和检查方法 |
| --- | --- |
| `update socket encryption failed` | 检查 daemon、设备序号、链路 slot、目标 port，以及运行态目标 socket 是否已经创建 |
| `update remote socket encryption failed` | 检查无线链路、remote slot、对端远程分发支持，以及对端运行态目标 socket 是否已经创建 |
| `query socket encryption failed` | 检查固件是否支持运行态查询、目标 socket 是否已创建，以及 slot 和 port 是否正确 |
| MiniDB 写入成功，但当前业务没有变化 | 属于预期行为；MiniDB 不修改当前 socket，如需立即生效还要执行不带 `--minidb` 的命令 |
| MiniDB 查询显示 `state=unset` | 当前 slot/port 没有持久化记录；按需要使用 `--minidb -e ...` 或 `--minidb -d` 写入 |
| 重启后没有恢复 MiniDB 配置 | 检查固件版本、port 是否在 `0-3`、slot 是否正确，以及目标 socket 是否由支持持久恢复的固件路径创建 |
| 命令成功但业务不通 | 对照检查 AP/DEV 两端的链路、port、mode 和 key，并确认两端都已完成切换 |
| 只有 SBUS 或 MAVLink 不通 | 分别检查 port 0 和 port 1；一个 port 的配置不会替代另一个 port |
| TAP 重连后配置恢复为启动值 | 属于预期行为；使用 `l4_tuntap` 自身的 `-e/-k` 参数重启两端 |
| 切换期间短暂丢包 | 两端暂时未对齐所致；暂停业务流量并连续完成两端配置 |

## 10. 验收清单

- AP 和 DEV 指向同一条无线链路。
- 两端使用相同 port 和 mode。
- AES 模式下，两端密钥完全相同。
- 两端运行态查询结果一致。
- 实际 SBUS、MAVLink 或 TAP 数据能够正常收发。
- 需要持久化时，两端 MiniDB 均已有预期记录。
- 重启或相关 socket 重建后，运行状态和业务通信仍正常。

## 11. 密钥安全建议

- 不要在生产环境复用本文中的示例密钥。
- SBUS 和 MAVLink 建议使用不同密钥。
- MiniDB 查询会打印完整 AES 密钥；密钥还可能进入 shell 历史、进程查看工具、终端录屏或日志，应限制命令及输出的访问权限。
- 更换密钥前先暂停对应 port 的业务，连续更新两端并完成端到端验证。
